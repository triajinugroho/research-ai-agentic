## Tujuan Lokakarya

Menemukan ancaman yang **spesifik** pada rancangan sendiri, merancang
penanganannya, dan menyatakan sisa risiko dengan jujur.

---

## Persiapan

| # | Yang disiapkan |
|---|----------------|
| 1 | Rancangan terpilih (T8) |
| 2 | Instrumen dan protokol (T9) |
| 3 | Bagian *Threats to Validity* dari 3 makalah dalam matriks T4 |

---

## Langkah-Langkah

### Langkah 1 — Menelusuri Rancangan Tahap demi Tahap (10 menit)

Untuk setiap tahap, tanyakan: **apa yang dapat membuat simpulan saya
keliru di sini?**

| Tahap | Apa yang dapat salah | Jenis validitas yang terancam |
|-------|---------------------|-------------------------------|
| Memilih subjek | | |
| Menghubungi subjek | | |
| Mengukur/mewawancarai | | |
| Menganalisis | | |
| Menyimpulkan | | |

> Menelusuri tahap demi tahap jauh lebih produktif daripada mencoba mengingat
> daftar ancaman. Ancaman yang ditemukan dengan cara ini otomatis spesifik
> pada rancangan Anda.

### Langkah 2 — Mengisi Tabel Ancaman (15 menit)

| Jenis | **Ancaman spesifik pada penelitian ini** | Kemungkinan | Penanganan | Sisa risiko |
|-------|------------------------------------------|-------------|------------|-------------|
| Konstruk | | T/S/R | | |
| Konstruk | | | | |
| Internal | | | | |
| Internal | | | | |
| Eksternal | | | | |
| Eksternal | | | | |
| Simpulan | | | | |
| Reliabilitas | | | | |

Minimal 8 baris, mencakup keempat jenis validitas.

| Ujian kolom "ancaman spesifik" | Contoh |
|--------------------------------|--------|
| ❌ Terlalu umum | "Bias seleksi" |
| ✅ Spesifik | "Responden yang bersedia diwawancarai kemungkinan yang paling aktif memakai sistem, karena daftar kontak diperoleh dari catatan peserta pelatihan" |
| ❌ Terlalu umum | "Keterbatasan generalisasi" |
| ✅ Spesifik | "Ketiga dinas berada di satu provinsi dengan kebijakan digitalisasi yang sama sejak 2023; pola yang ditemukan mungkin khas pada kebijakan itu" |

| Ujian kolom "penanganan" | Contoh |
|--------------------------|--------|
| ❌ Niat | "Akan berhati-hati dalam memilih responden" |
| ✅ Tindakan | "Menghubungi juga 10 pengguna nonaktif dari daftar sistem, selain peserta pelatihan" |

### Langkah 3 — Menyatakan Sisa Risiko (5 menit)

Untuk setiap baris, jawab: **setelah penanganan dijalankan, apa yang masih
dapat membuat simpulan keliru?**

Kolom ini menjadi bahan bagian *Keterbatasan* pada proposal. Penanganan tidak
pernah menghilangkan ancaman sepenuhnya, dan menyatakan apa yang tersisa
adalah bagian dari kejujuran ilmiah — bukan pengakuan kelemahan.

---

## Tinjauan Sebaya (20 menit)

Ancaman pada rancangan sendiri sulit dilihat karena peneliti sudah terbiasa
dengan asumsinya. Tinjauan sebaya sangat efektif untuk topik ini.

```markdown
## Tinjauan Sebaya — Ancaman Validitas
Penulis : [nama]     Peninjau : [nama]

Baca rancangan dan tabel ancaman teman Anda, lalu:

1. Sebutkan SATU ancaman yang tidak ada dalam tabelnya.
   Jenis  :
   Ancaman:
   Mengapa saya melihatnya:

2. Baris mana yang ancamannya masih terlalu umum?
   Tulis ulang menjadi spesifik:

3. Baris mana yang "penanganan"-nya masih berupa niat,
   bukan tindakan?

4. Baris mana yang kolom "sisa risiko"-nya kosong atau
   menyatakan risiko hilang sepenuhnya?

5. Bila hasil penelitian ini nanti mengejutkan, penjelasan
   lain apa yang mungkin selain simpulan penulis?
```

Butir 5 sering menghasilkan ancaman yang paling penting.

---

## Tantangan Tambahan

| # | Tantangan |
|---|-----------|
| 1 | **Penjelasan tandingan.** Tulis simpulan yang Anda perkirakan akan muncul. Lalu tulis 3 penjelasan lain yang dapat menghasilkan pola data yang sama. Untuk masing-masing, sebutkan data tambahan apa yang akan membedakannya. |
| 2 | Bandingkan tabel Anda dengan bagian *Threats to Validity* dari 3 makalah di matriks T4. Ancaman apa yang mereka sebut yang tidak ada dalam tabel Anda? |
| 3 | Untuk ancaman dengan kemungkinan **tinggi**, tentukan: apakah penanganannya masih dapat dijalankan dengan waktu yang tersisa? Bila tidak, apa yang harus diubah pada rancangan **sekarang**? |

Tantangan 3 adalah alasan bab ini berada sebelum pengumpulan data. Sebagian
besar ancaman tidak dapat diperbaiki setelah data terkumpul.

## AI Corner — Lokakarya 11

| Boleh | Tidak boleh |
|-------|-------------|
| Meminta AI menyebutkan jenis ancaman yang umum pada sebuah rancangan | Mengisi tabel ancaman Anda |

| **Meminta AI mengajukan penjelasan tandingan** | Meminta AI menilai kecukupan penanganan |

### Pemakaian yang Paling Bernilai

```
Rancangan saya: [ringkas]
Simpulan yang saya perkirakan akan muncul: [tulis]

Tugas Anda:
Sebutkan 5 penjelasan LAIN yang dapat menghasilkan pola data
yang sama tanpa simpulan saya benar.

Untuk setiap penjelasan tandingan, sebutkan data tambahan apa
yang akan membedakannya dari simpulan saya.

Jangan menilai apakah rancangan saya baik.
```

Penjelasan tandingan yang tidak terpikirkan peneliti adalah tepat apa yang
akan ditanyakan penguji — dan menemukannya sebelum data dikumpulkan masih
memungkinkan rancangan diperbaiki.
